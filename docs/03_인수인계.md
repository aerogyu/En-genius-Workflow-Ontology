## 5. 함정 기록 (다시 밟지 말 것)

**형제 저장소에서 이어받은 것**
- 여러 줄 편집은 Edit/Write 도구로 — bash heredoc 속 파이썬 문자열·역슬래시가 무너진다. 치환은 대상이 1개인지 assert.
- 파일은 LF (`newline="\n"`). 커밋 전 `git diff --check` (`schema/generated/` 는 .gitattributes 로 공백 검사 제외).
- `.bat` 은 **영어 ASCII + CRLF** — 한국어 Windows 의 cmd 는 .bat 을 cp949 로 읽는다. `rem` 줄에도 한글 금지 (`tests/test_scripts.py` 가 잡는다).
- `env.bat` 이 `PYTHONUTF8=1` 을 켜고 모든 .bat 이 env.bat 을 거친다. 꺼지면 linkml·yaml 이 한국어 YAML 을 cp949 로 읽어 schema 가 실패 — `tests/conftest.py` 가 한 줄(`Exit: …`)로 멈춘다.
- Windows 에서 `os.kill(pid, 0)` 은 프로세스를 **죽인다** (존재 확인용으로 쓰지 말 것).
- Python 3.10: f-string 안에 같은 따옴표 중첩 불가, `{}` 안 역슬래시 불가.
- LinkML 생성기 함정 — 남의 어휘(P-Plan 등) 덮어쓰기, 열린 루트, 같은 IRI 속성 경고, 라벨 xsd:string. `schema_gen.py` 가 정리한다. LinkML 판을 올리면 `schema --check` 와 SHACL 테스트로 다시 확인.
- linkml 은 `schema` 명령에서만 import — 빌드는 `schema/generated/` 만 읽는다 (홈 폴더 없는 환경에서 linkml→pystow 가 실패, V11).
- UAC·보안 창은 대신 누르지 않는다.

**W0 에서 새로 밟은 것**
- Git Bash 에서 `cmd.exe /c` 에 따옴표 든 인자를 넘기면 MSYS 가 `\"` 로 바꿔 cmd 가 못 읽는다 (그리고 `/c` 는 `MSYS_NO_PATHCONV=1` 없이는 `C:\` 로 바뀐다).
  .bat 확인은 파이썬 `subprocess.run(문자열)` 로 탐색기와 같은 명령줄 `cmd.exe /c ""<bat>" "<인자1>" "<인자2>""` 를 그대로 넘기고, stdin 에 엔터, 환경에서 `PYTHONUTF8`·`PYTHONIOENCODING`·`PYTHONPATH` 를 빼고 돌린다 (7장).
- `for /f` 로 파이썬 출력을 받으면 cmd 가 코드 페이지(cp949)로 읽어 한글 경로가 깨진다 → .bat 은 경로를 변수로 되받지 않는다. 판단·실행은 `scripts/bat_helper.py` 가 끝낸다.
- cmd 인자 `"C:\x\"` 의 끝 `\"` 는 따옴표 글자로 남는다 (MSVCRT 규칙: `C:\x"`) → `bat_helper.resolve_arg` 가 걷어 낸다.
- 탐색기 끌어다 놓기는 공백 있는 경로만 따옴표로 감싼다 — 공백 없이 `&` 가 든 경로는 `%*` 에서 끊긴다 (드묾, 처리 안 함).
- Write 도구로 쓴 .bat 은 LF — 저장 뒤 CRLF 로 바꾼다. `.gitattributes` 가 `*.bat text eol=crlf` 라 index 는 LF, 작업 트리·zip 은 CRLF.
- 저장소 예시 폴더를 build 하면 그 폴더의 `_registry` 를 다시 쓴다 (내용이 같으면 변경 0). 테스트는 예시를 임시 폴더에 복사해서 돌린다.
- `pause` 의 한국어 문구는 cp949 — 캡처에서 깨져 보이는 것은 정상.
- 이 환경에서는 변수가 든 `rm -rf` 가 권한 거부될 수 있다 — 임시 폴더는 새 이름으로 만든다.

**W1 검토 수리에서 새로 밟은 것**
- Git Bash heredoc 은 `<<'EOF'` 로 따옴표를 쳐도 내용의 `\\` 가 `\` 로 줄었다 — 테스트 문자열 `"data\\real\\ 아래"` 가 `\r`(CR)이 든 문자열이 되어 실패.
  역슬래시가 하나라도 든 내용(Windows 경로·정규식·markdown `\|`)은 **Write/Edit 도구로만** 쓴다. heredoc 파이썬은 역슬래시 없는 치환에만.
- 레지스트리는 **계산(assign_ids)과 쓰기(write_registry)가 나뉜다** — 쓰기는 pipeline.run 이 산출(TTL·계약·그림·canonical)을 다 쓴 뒤.
  판 검사(check_versions)는 레지스트리 계산 **뒤**에 돈다 (이번에 이은 계약 개명 = 옛 key 동결본도 읽기). 순서를 바꾸지 말 것.
- 동결본(_released)의 def 는 품은 계약 정의를 `refs` 로 품는다 — `canon_def(i, m)` 처럼 m 을 넘겨야 스냅샷이 생긴다 (m 없이 부르면 refs 없음).
- 검토 에이전트가 저장소 `workflows/examples/` 안에 `_run_<이름>_<숫자>/` 사본 폴더를 남긴 적이 있다 (git 추적 밖). 커밋은 `git add <경로>` 로만.
